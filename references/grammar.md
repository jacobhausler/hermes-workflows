# Graph grammar and authoring boundaries

Workflow 1.1.1. Minimal form: `workflow{action:"run", graph:{"name":"check","nodes":[{"id":"a","type":"agent","goal":"Return a fenced JSON object with key ok=true"}]}}`. The run action's `name` overrides `graph.name`; otherwise the graph name is used, then `workflow`.

## Nodes and data

Graph-level `defaults:{schema, timeout, max_turns, reasoning, provider, model, context, require_route}` fills any agent key the author left unset (`defaults.context` is prepended once to each agent's own context); explicit node keys win. Agent fields: `id`, `type:"agent"`, `goal`, `after:[ids]`, `context`, `schema`, `inputs`, `model`, optional `provider` paired with a nonempty model, `reasoning`, `toolsets`, `max_turns`, `timeout`, `run_budget`, `shape`, `repo`, `fanout`, the route-integrity key `require_route` (below), and the optional team fields `profile` and `requires` (below). `shape:recon|build|review|publish` fills `max_turns`/`timeout` from measured p95 presets when unset (default shape `build`). `repo: <path>` (absolute or run-dir-relative) declares the git lane the node owns: at commit the runner checks `git status --porcelain --untracked-files=no` of that lane, and a done/partial over a lane with uncommitted TRACKED changes commits `failed` `error_class:"incomplete_work"` with `lane_dirty` porcelain instead of handing off an uncommitted fix downstream would never see (the dad50be0 false-green shape). Never an auto-commit; commit in the lane, then amend/re-run re-drives the node. Untracked files never dirty a lane; git being unable to answer fails open. `echo` nodes (`{id, type:"echo", after, output}`) commit `output` verbatim with no spawn. Unknown keys (including `agent.when`) are rejected before write/spawn. The node's `schema` constrains fenced JSON: the runner appends the reply contract (required keys + types) to the prompt itself, extracts the last balanced JSON object from noisy stdout, and gives the child one correction retry — authors never write contract prose. Keep work idempotent: unfinished work may replay. An explicit provider routes via the child `--provider` flag; unset model uses the seat default even for fan-out.

`require_route` (bool; default TRUE on nodes that pin an explicit model, never baked when left unset): fail-closed pinned routes (#25). The door's submit ping AFFIRMATIVELY proving a pinned route dead — or answering from the fallback ladder (recorded route != pinned route) — REFUSES the launch (`route_unavailable`) instead of silently billing another model; `false` opts into the ladder explicitly. Infra-absence (core unimportable, offline seat) stays `unknown` = warn-only: missing evidence never blocks. A proving-alive ping bakes the door-only `route_verified` annotation (author-supplied values are stripped at the door and dropped again at resolve — never trusted from an author, never forged through `save`; the runner's closed key set carries it so the committed `graph.json` loads) and the runner then holds the committed `served_model` to it — a contradiction commits `failed`/`route_unavailable`. `require_route`/`route_verified` never participate in a node's fingerprint (like budgets: policy/annotation, not work), so a door bake or a defaults flip cannot un-freeze committed nodes. A node's death also lands in the seat quota cache when classed `fatal_quota` (#24): a 429 carrying its own reset horizon fails on the first attempt — the bounded ladder can't beat a multi-day reset — and the door refuses a re-launch on that model until the horizon passes, one recovery ping first.

`profile` (agent only, optional): run that node AS a named teammate profile — DELEGATION, not isolation: the child runs with the TARGET profile's SOUL, memory, `.env` and tools, same UID, one owner; no isolation is claimed or possible. Node-level only (fan-out items carry no profile of their own). The door renders `{run.KEY}` in `profile` BEFORE validation, so a graph can name its teammate per launch (`"profile":"{run.reviewer}"`). Validation completes before any write/spawn: the name is a non-empty profile DIRECTORY whose `config.yaml` exists; `default` is never a target; the target's owner-written `<profile_home>/workflow_team.json` lists the LAUNCHER in its `accept_from` array ("default" is a legal launcher name). The launcher identity is read from the door's own HERMES_HOME, never from a graph arg. A target deleted between validation and spawn is a typed `error_class:"spawn"` failure (`profile gone: <name>`) — never a launcher fallback.

`requires` (agent OR gate, optional): output preconditions on ancestors — `{"<ancestor>": ["field","dotted.path",…]}`; every key must be in the node's `after` closure and every path a non-empty string, or the graph is rejected before write/spawn. At schedule time (before the spawn) each path resolves against the ancestor's committed output (done/partial): a missing OR null value makes the node `failed` with `error_class:"precondition"` (`error: precondition unmet: <ancestor>.<path>`, `output.missing` lists the paths) with ZERO spawns, and the run fails on the existing failed path (`blocked`, WORKFLOW_FAILED, downstream blocked) — a reader can never discharge an obligation on a null output. The retry ladders never see a precondition death; a resume re-evaluates it (supply the missing field via `amend` and the node spawns). 1.0.x `skipped` semantics are untouched: a graph that WANTS skip-on-missing uses the existing `when` gate + `on_skip:"prune"` path. A node without `requires` facing a null upstream spawns exactly as before.

`after` schedules AND injects: every direct parent's committed output lands under `## Inputs` automatically (8 KB per parent, truncated with a marker). `inputs:["a", "a.key"]` picks a dotted path or a non-parent ancestor, failing loudly on missing paths; a parent named in both appears once. A gate cannot declare `inputs`, but a downstream agent can read its committed output. Fan-out uses `fanout:{"items":[...],"goal":"Audit {item}"}` or `items_from:"a.items"`; `goal` is optional when every item carries its own (the node goal then prefixes each item prompt). `{item}` is the item value; `{index}` is the zero-based item number. Dict item fields may be interpolated, and a dict item's nonempty `goal` overrides the template. Unreferenced keys are not injected. The `fanout` closed set is exactly `{items | items_from, goal, schema, quorum}` — any other key is rejected with `unknown key; allowed: [items, items_from, goal, schema, quorum]`; `schema` is an object constraining EACH item's reply (same reply-contract rules as the node `schema`). `quorum` (optional) races: once N succeed, the rest are cancelled (`error_class:cancelled`, excluded from failure math); without it the fan-out waits for every item. A reducer with `inputs` can aggregate; optional schema-defined feedback arrays need no new workflow action or mandatory worker boilerplate.

## Gates and branches

A gate has `type:"gate"`, `after`, optional `question`/`options`, `when`, `on_skip`, `default_option`, `hold_timeout`, and optional `requires` — gates take the same output preconditions as agents (`failed` with `error_class:"precondition"`, zero spawns; see Nodes and data). Human gates hold until release; with `hold_timeout` (s) the runner parks at zero tokens and, at expiry, releases with `default_option` (must be one of `options`; event `gate.auto_released`) or, without one, logs `gate.expired` once and keeps holding. `wait:{"wait_s":N}` is a timer; `wait:{"until_argv":["program","arg"],"every_s":60,"timeout_s":3600}` rechecks fixed argv without a shell. A machine timeout is failure, not approval. Gate options are answer DATA; a "no" response alone does not prune work.

Bounded `when` reads `out.<ancestor>.<path>`, with string/number/boolean literals (`true`, `false`, `True`, `False`), comparisons, and/or/not and parentheses. A false predicate defaults to `on_skip:"prune"`: the gate and descendants with only skipped dependencies become terminal-skipped. Explicit `on_skip:"pass"` skips the gate question but lets descendants proceed. A true predicate still holds or waits; a predicate error fails safe rather than skipping. For mutually exclusive arms, use two complementary gates, each with its agent, then a mixed join. See tested `examples/approve-publish.json` and `examples/branch-on-verdict.json`. A missing upstream input fails rather than injecting an empty value. There is no native vote/loop/foreach engine.

## Staleness and replay

Each new commit (including gate answers, spawn identities and runner exits) stamps its fingerprint rule. Readers recompute against the current graph under THAT recorded rule, not necessarily the reader’s default. A definition or ancestor edit invalidates the affected record; an unknown rule fails closed. Unstamped historical records replay when any known rule matches the current graph — two rules agreeing on the same hash prove the definition is unchanged, so an equal-hash pair no longer fails closed (a real definition change matches no rule and still does). A budget-only edit invalidates old-rule commits but not new-rule commits. A pre-upgrade reader already loaded in a long-lived serve process must restart after deployment.

## Top-level provenance

A graph may carry a top-level `provenance:{owner, source, saved_at, source_digest}` object (closed key set; unknown keys rejected). The door writes it into a library entry ONLY when `save` supplies `source` (≤200 chars: repo path, URL, skill) or the saving door runs under a named profile (owner = launcher profile); a default-profile save without `source` keeps the pre-1.1 bytes exactly. `source_digest` is a sha256 over the canonical `nodes` JSON — deliberately named apart from `graph_fingerprint`, whose rule-stamped meaning is unchanged. `library` rows show owner/source/source_digest only when present; `run from:<name>` stamps `run.json.graph_source = {name, owner, source, source_digest}` only when the library graph carries provenance. Provenance is attribution metadata, not an ACL: nothing reads it to allow or deny.

## File-authored graphs

Use `graph_path` with run/save/amend for a caller-authorized absolute local regular UTF-8 JSON file, at most 1 MiB, no final symlink. Choose exactly one source: inline graph, graph_path, or run's `from` / save's `run_id`. Validation completes before writing or spawning. Save to the library and replay with `from` for repeated use; graph_path is valuable for an unsaved local graph or replacement amendment. Neither feature asserts a universal tool-argument length limit.

A shared file may state its dialect with a top-level `grammar` key (`"wf/1"`; absent = `wf/1` for every pre-#32 file). A value this reader does not support is refused before any write or spawn, with the supported list in the error. Like `provenance`, `grammar` is a top-level annotation — never part of a node, so `def_hash`, `efp`, `graph_fingerprint` and `source_digest` are unchanged by it. The publishing convention (`<name>.workflow.json`, provenance, pinned digests, the no-code note) is [portable](portable.md).
