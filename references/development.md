# Contributor checks (not ordinary user setup)

The plugin code is stdlib-only and imports host modules lazily. Test source from an isolated checkout, with fixture homes under the checkout or unique temporary directories there; never point tests at an active user's home. Use the backend Python from that checkout's environment, for example `python3 tests/test_engine.py` from the project root, and run all `tests/test_*.py` files serially. Run the frontend check with `node --check desktop/plugin.js` and `node tests/test_fanout_ui.mjs` where Node is available. Record each command's real exit code; do not convert failed tests into a passing aggregate. The release integrator owns the complete clean-copy sweep and package validation, not the skill.

For an apparent bug: reproduce it, write a focused RED check, then make a minimal source fix and rerun that check plus the relevant existing suites. Inspect source and live host API before believing an old feedback receipt; historical counts are not an open-ticket list. Keep runtime dependencies and plugin writes separate from documentation. The desktop app and backend plugin can live on different machines; testing JS syntax in one location does not prove the app loaded it. No production restart, installation, or publication is implied by a green source test.

Lane hygiene when a build lane runs under the workflow runner (#37): never check a base ref out over a dirty tree to produce a RED run; commit tests first and use a throwaway detached worktree or a named stash, and bank a WIP commit before the turn cap. If a lane still dies with unbanked work, `python3 scripts/lane_recover.py --run <id> --node <node> --out <dir>` replays its journaled write_file/patch calls from the profile's state.db (read-only) into a restore dir; `tests/test_lane_recover_8edcc9bf.py` pins the replay against a synthetic db and `tests/test_lane_hygiene_preamble_8edcc9bf.py` pins the preamble as prompt-side only.
