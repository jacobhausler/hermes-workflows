# Run operations and read model

Use `workflow{action:"run", graph:<object>}` (or `from:<saved-name>`, or `graph_path:<absolute-local-JSON-file>`), then `status` and `wait` with the returned `run_id`. For a reusable graph, `save` first and `run from:<name>` next; `library` lists it. `graph_path` is for an unsaved caller-authorized local file on run/save/amend, not a remote path. `/wf` is an optional shelved-graph front door.

A run may be running, held, interrupted, done, failed or stopped. Running requires a live process with the exact runner command and run identity; a persisted PID or parked marker is not sufficient. Held gates and interrupted runs do not count as running. List responses include full-census `counts` and `total` even when the recent-runs page is truncated. `interrupted` means unfinished work with no live runner: inspect saved outputs and uncertain side effects before explicitly resuming with `wait`. A recorded fatal runner crash is `failed` and needs correction/amend rather than repeated wait/respawn. `wait` can return a "call wait again" note before a terminal state to stay inside the host deadline. A held human gate supplies question/options/context: ask the owner, then release with the exact answer and wait again. A machine gate may park without a child; read its check attempt, last exit/tail and deadline.

`status.nodes` uses committed results for scheduling and projects an uncommitted child spawn as running only when its recorded process identity is still verified. `blocked_by` points to unfinished ancestors. Child spend metrics are cumulative across attempts/graph amendments. Liveness and heartbeat come only from exact, currently verified child process/session identities: `active_spawns` lists all active fan-out children, while `active_spawn` retains the first for existing consumers. Node and per-item metrics do not count old unended database rows as live; missing current activity means unknown idle, not zero. Not every run has a metrics row. Missing API-call evidence is unknown, never zero; retry after uncertain effects may duplicate them. Failed records may carry typed errors, log paths and attempts. A turn-cap death (`cap_exhausted`) is typed only when the child's core quiet-turn report carries the loop's own budget stamp (`max_iterations_reached(n/m)`); prose about turn limits is never trusted, and an untyped budget death stays `unknown`. The error line names the log path and the write-first/reserve-final-turns authoring fix. Stale runner exits do not suppress amended work. A pruned/skipped node is terminal, not done output.

`steer` queues text for a future child spawn; it does not inject into a running child or reopen a terminal run. To change a graph, submit the entire replacement via `amend`; `dry_run:true` previews added/removed ids plus changed/will_rerun/unchanged. Added nodes and their downstream work appear in `will_rerun`; matching committed results replay-skip. Stop is not rollback; reconcile external effects before rerunning.

## Small, parent-gated escalation recipe (no new engine feature)

Use a terminal, decision-only agent node with no automatically runnable work descendants. Its ordinary schema-defined final JSON can contain `needs_escalation: true` and a short reason (the node schema must actually permit these fields). The parent inspects that exact value and any external effects, selects an explicit model and amends the graph with original committed inputs plus a bounded factual handoff. Check `dry_run`'s `will_rerun` before applying. A timeout remains a failed node, not a safe auto-retry: the parent investigates and decides. Never use this on a work-product node with downstream execution; schema-valid JSON is committed as done even if its text requests escalation. This recipe adds no tool, status, automatic fallback or guarantee of side-effect rollback.

Desktop cards use `::workflow{id="<run_id>"}`. The quoted directive is owner-confirmed to render when manually emitted, but automatic insertion is bounded by the host's final-output hook: a blank/interrupted final may bypass it. A launch response also supplies the quoted card to the agent; manual emission is not evidence of automatic delivery. Backend and desktop plugin installations are separate.
