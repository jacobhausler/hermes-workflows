fix(desktop): the refusal stamp gets a render surface on the node fact sheet (est-zmpx8)

Residual from the #584 peer review. #584 put `refusal` into `wfcommon.FACT_KEYS` and
the door's `node_facts` whitelist, so a spent-cap boot carries
`refusal=lifetime_cap_spent` through the ONE node-truth read — but Explorer V2 renders
node facts by NAMED sections rather than by iterating the payload, and the desktop half
had no row for it: the machine-readable verdict rode the app payload unshown, so an
operator on the app saw only `transport_exhausted` plus prose and still had to read the
message to learn that the death is a REFUSAL (re-running the same graph dies identically
until the ledger resets).

`desktop/plugin.js` only — the read model, door and runner are untouched:

- the fact sheet renders `refusal` beside the death facts (after `error`, before
  `attempts_log`), guarded by `factKnown` and printed through `unk` — the treatment
  `error_class` has had since WF-03: a present stamp renders verbatim, an absent one
  (the read model substitutes the literal `unknown`) HIDES its section. Honest absence
  on screen, never a fabricated value (AGENTS rule 8).
- `'refusal'` joins the `ITEM_FACTS` fallback list in FACT_KEYS order
  (`error_class` → `refusal` → `error`), so a picked fan-out item's synthesized facts
  stay key-complete instead of silently dropping the row.
- `fanItems` carries the per-item stamp the way it already carries `errorClass`
  (`rec?.refusal || ev?.refusal || null`), so an item whose committed record holds a
  refusal reaches the panel and one without it reads `null` and hides.

from the source and renders them with stub JSX (the `test_node_panel.mjs` idiom) against
facts CAPTURED LIVE from the read model — `tests/fixtures/refusal_capture.py` commits
`wf.py`'s `_window_spent_record` output verbatim into a run dir and prints

dashboard `_view` merges, never a hand-typed fixture. P1 is the acceptance (the stamp on
