perf(dashboard): the /runs census leaves the event loop — threadpool dispatch + TTL snapshot

The workflow card census (dir walk + ONE batch lock-probe child + a per-dir
view + a per-row logs check) ran SYNCHRONOUSLY inside an `async def` route,
so on the production census (~560 run dirs, 0.6-1.3s) it froze the event
loop of the serve process that also hosts every agent lane — every other
webui call queued behind one dashboard poll (est-ey31s, agents.hausler.cc
"webui not working"). All four dashboard GET routes are plain `def` now
(Starlette threadpool, the shape /api/sessions already used), scans collapse
through a 2s TTL snapshot with a double-checked lock (hermes-agent's
_TOPOLOGY_CACHE shape), and the gate-release POST invalidates so a UI action
reflects in the next response. Default answer byte-contract-identical;
`?offset=&limit=` pages slice the ONE census with census-wide totals.
Measured: /health p95 during scans 666ms -> 74ms; repeat polls 625ms ->
18ms. Tests: tests/test_runs_offloop_ey31s.py (red at base, green at head).
