### Fixed

- Door (est-j14j3): `defaults.schema` CONTENT now passes the same schema-shape
  law a node `schema` gets. The `schema_check` closure was extracted into
  module-level `_schema_check(schema, field, report)` — the one shared helper
  (the `_retry_block_errors` pattern for node-key/defaults-key shapes) — and
  `_defaults_errors` calls it over the `defaults.schema` subtree, reporting
  graph-level rows with field paths like
  `defaults.schema.properties.pr_number.type`. Before, the defaults pass
  checked only dict-ness, so a JSON-Schema union type (`"type": ["integer",
  "null"]`) in `defaults.schema` passed `workflow validate`, got baked into
  every agent node by `apply_graph_defaults`, and the runner boot refused the
  baked nodes — a dead run with lost claim stamps and a false green on
  validate. One fault line per authored occurrence, pointing at the schema
  path; door and boot refusal words come from the same code line and cannot
  drift (pinned by `tests/test_defaults_schema_union.py`, both directions).
