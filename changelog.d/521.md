fix(validator): reject hybrid human-question + machine-wait gates

A gate carrying BOTH a human question and a machine wait is refused at
submit (`question applies to human gates, not machine wait-gates`), the
same way `default_option` already is. Fan-out wider than the seat cap
rendered exactly that hybrid and died seat_wait with no operator-visible
remedy; it now refuses at the door carrying the max_seats remedy.
`references/grammar.md` names the law; the four pre-existing hybrid
fixtures (run_binding / sprint101 / runctx_contract / include_door) and
the shipped `examples/ops/incident-response.json` probe gate migrated to
pure machine-wait shape — caller migration belongs to the law.

sibling byte-pin, independence).
